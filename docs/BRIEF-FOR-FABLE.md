## 0. How this document is produced (the pipeline)

```
screenshots + brief            CLAUDE                      KIMI audit                 FABLE
──────────────────►  docs/PROMPT-FOR-CLAUDE.md  ──────►  every ID verified  ──────►  this brief
                     design review + spec pack            accept / reject / remeasure      build, pass by pass
```

The audit is mechanical, not a reading. For every row Claude returns:

| Gate | What is checked | Tool |
|---|---|---|
| **G1 Evidence** | Every "current state" claim cites a screenshot frame or `path:line`, and that thing is actually there | eyes + `read_file` |
| **G2 Contrast** | Every colour pairing proposed is re-measured in both themes | `node scripts/contrast-audit.mjs --strict` |
| **G3 Law** | No row breaks: the one rule, no custody, honesty labels, no off-origin request, red-is-danger, plain language, nothing deleted | checklist + tests |
| **G4 Feasibility** | Token names, component props and file paths exist; the change is CSS/inline-SVG only, no new dependency | `tsc`, `eslint`, `scan-bundle` |
| **G5 Testability** | Each acceptance line can be asserted (in vitest or a browser suite) without loosening an existing assertion's meaning | test files |
| **G6 Effort honesty** | An "S" really is small; an "L" is split into shippable passes | judgement |

Verdicts: **ACCEPT** (goes into §4–§7 verbatim), **ACCEPT-WITH-EDIT** (small correction, quoted in the
brief), **REJECT** (with reason, kept in the audit log so it is not silently re-proposed later).

## 1. Who you are (Fable)

You are the implementer, not the designer. A principal designer has already specified the interface, and
an engineering lead has audited that specification against the codebase. Your job is to build exactly
what is specified, in the order given, and to prove each pass with gates and screenshots. Creativity is
welcome in *execution detail* (how a transition is composed in CSS, how an illustration is drawn in SVG);
it is not welcome in *decisions already made*.

If you believe a specification is wrong, stop and report it — do not quietly improve it.

---

## 2. The product, in five lines

`slip` is a free, open-source, non-custodial, serverless point of sale for Bitcoin. A merchant pastes
public wallet material once and every sale is paid straight into their own wallet. No backend, no
accounts, no analytics, no cookies, no CDN, no runtime font request. slip **cannot spend**. One deployable
file: `dist/index.html`. Live: https://slip.giveabit.io · Repo: `kitsboy/slip`, branch `master`, MIT.

## 3. The build contract (applies to every pass)

```
npx tsc -p tsconfig.json --noEmit          # 0
npx eslint .                                # 0
npx vitest run                              # never fewer than before, all green
npm run build                               # single file; CSP hash regenerated by the build
node scripts/scan-bundle.sh                 # no off-origin strings
node scripts/contrast-audit.mjs --strict    # every pair AA
node scripts/docs-audit.mjs --strict        # every panel still documented
npx vite preview --port 4181 --strictPort   # then:
node tests/e2e/run-all.mjs "http://[::1]:4181/"   # 12/12
node scripts/shots-matrix.mjs               # 30 frames, then look at them
node scripts/demo-check.mjs https://slip.giveabit.io/   # 8/8 after deploy
```

Rules of engagement:

1. **One pass, one commit, one deploy.** `SLIP_NOTE="…" bash scripts/deploy.sh minor|patch`, then verify
   the live DOM. The till must keep selling through every pass — never a big-bang rewrite.
2. **Never weaken a test to pass a redesign.** If a selector changes legitimately, update it and name it
   in the report; the assertion must keep its meaning (assert something is visible/readable — never
   loosen a scroll-distance check into a no-op).
3. **Frozen:** money maths, ledger and storage keys, the CSP shape, every honesty string, the one rule,
   the no-custody rule, and the "show technical names" default of **off**.
4. **No new dependency.** CSS and inline SVG only. Any font must be a vendored `woff2` subset under
   `public/`, referenced locally, and `scan-bundle` must stay clean.
5. **Do not delete a tool.** Fold, relabel, move — never remove.
6. **Screenshots are part of the deliverable.** Extend `scripts/shots-matrix.mjs` for anything you touch;
   look at the frames; fix what you see, not what you assume.
